We need to come up with a good way to provide a global and/or canonical MCC CustomWrapper template.

This is complicated somewhat by the way the MCC system requires users to upload code with the following pattern 
For example:
``` vhdl
-- this is the top file associated with the reference DCSequencer module. 
-- note the naming convention / module insantiation style 
-- 'Top.vhd' 
library IEEE;
use IEEE.Std_Logic_1164.All;
use IEEE.Numeric_Std.all;

architecture DCSequencer of CustomWrapper is
begin
    DC_SEQUENCER: entity WORK.DCSequencer
        port map (
            Clk => Clk,
            Reset => Reset,
            DataIn => InputA,
            HIThreshold => signed(Control0(31 downto 16)),
            LOThreshold => signed(Control0(15 downto 0)),
            DataOutA => DataOutA,
            DataOutB => DataOutB
        );
end architecture;
```


There -is- a corresponding entiy block, provided  in @mcc_templates/mcc-Top.vhd BUT
Users do not need to include it (in fact, they cannot) when uploaded to MCC

I would like to come up with a consistent strategy that will ensure that
- users can locally compile and test with ghdl 
- we will automatically help with the top level moku CustomWrapper shenanigans

Thoughts?
