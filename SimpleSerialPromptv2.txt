# SimpleSerial V2 TX Module - Quick Start Prompt

## Context
We successfully implemented SimpleSerial V1 TX (ChipWhisperer protocol). Now we want to implement SimpleSerial V2 TX, which is the next-generation protocol with binary encoding and higher performance.

## Task
Implement a complete `volo_simpleserial_v2_tx.vhd` module with full CocotB test suite.

## SimpleSerial V2 Protocol Specs
- **Baud Rate**: 230400 (6× faster than V1)
- **Encoding**: Binary COBS (Consistent Overhead Byte Stuffing)
- **Framing**: 0x00 delimiter (COBS ensures no 0x00 in payload)
- **Format**: `<0x00><len><cmd><payload><crc><0x00>`
  - 0x00 = Frame delimiter (start/end)
  - len = COBS-encoded length byte
  - cmd = Single command byte
  - payload = Binary data (0-252 bytes, COBS-encoded)
  - crc = CRC16-CCITT (optional, often omitted)
  - 0x00 = Frame delimiter (end)

## Key Differences from V1
1. **Binary, not ASCII**: Raw binary data, no hex encoding (2× bandwidth)
2. **COBS encoding**: Eliminates 0x00 bytes in data, uses 0x00 as delimiter
3. **Higher baud**: 230400 vs 38400 (6× faster)
4. **CRC protection**: Optional CRC16 for integrity checking
5. **Variable length**: Explicit length byte, supports up to 252 bytes payload

## Implementation Strategy
1. **Reuse UART TX core**: Same `volo_uart_tx_core.vhd` with BAUD_RATE=230400
2. **Add COBS encoder**: New function in `volo_uart_pkg.vhd` or separate package
3. **Add CRC16**: Optional CRC16-CCITT calculator
4. **FSM states**:
   - IDLE ’ SEND_START_DELIM ’ SEND_LEN ’ SEND_CMD ’ SEND_PAYLOAD ’ SEND_CRC ’ SEND_END_DELIM ’ IDLE
5. **Interface**: Similar to V1 but with `payload_len` up to 252

## COBS Encoding Quick Reference
- **Purpose**: Replace all 0x00 bytes with non-zero values
- **Method**: Replace 0x00 with distance to next 0x00 (or end)
- **Overhead**: 1 byte per 254 bytes (0.4% worst case)
- **Example**: `[0x00, 0x11, 0x00]` ’ `[0x01, 0x02, 0x11, 0x01]`
